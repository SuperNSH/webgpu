# react-native-webgpu inventory (commit 06599f9), checklist for the NSH/wgpu 1:1 port

Source: [`wcandillon/react-native-webgpu`](https://github.com/wcandillon/react-native-webgpu/tree/06599f9). TS lives in `packages/webgpu/src` (paths below are relative to it unless noted), C++ in `packages/webgpu/cpp/rnwgpu`. Upstream backend is Dawn (`dawn: chrome-m158`, package.json). Everything below was read from the source; wgpu 29 columns are from knowledge of wgpu, not verified against the 29 docs: re-check each "H"/"E"/"?" row when porting.

Legend for the wgpu column: **Y** = direct wgpu API; **E** = emulate in glue (wgpu has no equivalent, behaviour reproducible); **H** = needs `wgpu::hal` / unsafe platform interop; **N** = not possible or meaningless on wgpu; **?** = verify.
"RN-only" = depends on React Native (Fabric view, JSI, worklets) and has no NSH meaning; the port needs an NSH replacement or can drop it.

---

## 1. Public TS exports

Entry resolution: `index.tsx` (native) re-exports `./main` + `./constants` + `installWebGPU` + animation frame fns + types. `main/index.web.tsx` (web) re-exports a subset (no NativeBufferView, no importDevice, no WebGPUModule, no installWebGPU). Install order is load-bearing: `import "./main/installNative"` must be the first import (index.tsx:9, main/index.tsx:6) because `constants.ts` reads globals at module evaluation; `installNative.ts:11-20` calls `WebGPUModule.install()` and throws at import if the `RNWebGPU` global is missing.

## 2. Spec classes (`cpp/rnwgpu/api/*.h`) as JS sees them

Every class also exposes `__brand` (string = class name, used by worklet serializer; not spec) and a prototype installed via `installConstructor` in `RNWebGPUManager.cpp:115-150`. Constructors are installed globally only for the classes in that list; `Canvas`, `ImageBitmap`, `NativeBuffer`, `VideoPlayer` have no global constructor. ### 3a. Harness in 10 lines

1. `jest.config.js`: preset `@react-native/jest-preset`, `globalSetup: globalSetup.ts`, `globalTeardown: globalTeardown.ts`, `jest -i` (serial), `jest.setTimeout(180s)` (setup.ts:~30).
2. `globalSetup.ts` starts an HTTP+WebSocket server on `E2E_PORT` (default 4242): WS for RPC, HTTP serves `__tests__/assets/*.png` (`fixtureUrl`), runs `adb reverse`, waits up to 10 min for the example app's *Tests* screen to connect (hello message `{OS, arch, host}`), and stores a `Channel` (`components/Channel.ts`) on `global.testChannel`.
3. `Channel` = JSON RPC `{id, method, params}` -> `{id, result}|{id, error}`; 30 s per-call timeout, late replies dropped; app side is `apps/example/src/serve.ts`.
4. `setup.ts` `client.eval(fn, ctx)` serializes `fn.toString()` + JSON ctx; the app `eval`s it with `{device, gpu, adapter, ctx, canvas, shaders, urls, assets, mat4, vec3, mat3, workletDeviceStress?, workletSerialization?, exportedFlags?, views?, importSkiaDevice?}`. Return values must be JSON (BigInt come back as decimal strings).
5. Because the function is stringified: no closures, no array destructuring/object spread helpers (Babel helpers absent on device), values passed through `ctx` argument only.
6. Alternative clients selected by env: `REFERENCE=true` (puppeteer Chrome, `--enable-unsafe-webgpu`, regenerates reference behaviour), `NODE_WEBGPU=true` (`dawn.node`, in-process, with JS polyfills for `createImageBitmap`), default = real device. `client.OS` in {ios, android, web, node} gates tests.
7. `ctx`/`canvas` in tests is an offscreen render target (`DrawingContext`/`NodeDrawingContext`/`GPUOffscreenCanvas`): `getCurrentTexture()` plus `canvas.getImageData()` readback to `{data:number[], width, height, format}`.
8. Image checks: `encodeImage(bitmap)` -> PNG (swizzles bgra8unorm->rgba), `checkImage(png, "snapshots/x.png", opts)` uses `pixelmatch` `threshold 0.1`, `maxPixelDiff 200` (setup.ts:~850-870); writes `<name>.png.test.png` and `-diff-test.png` on failure; if the baseline file is missing it is written and the test passes.
9. Fixtures: `Di-3d.png`, `moon.png`, `saturn.png`, `f.png` from `apps/example/src/assets/`, decoded host-side with `pngjs` and injected as `assets.di3D/moon/saturn` and `urls.fTexture`; `wgpu-matrix` as `mat4/vec3/mat3`.
10. Some specs are host-only and don't use `client` at all: `Channel.spec.ts` (fake socket), `FeatureNames.spec.ts` (parses C++ headers), `WebPolyfill.spec.ts` (fake DOM).
